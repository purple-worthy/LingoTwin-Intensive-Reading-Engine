## 四、 v14.2 · 数据库凭据移入后端（顺手治好 Chrome「保存密码」弹窗）

## 五、 v14.3 · 插件开关状态持久化（"段落滑动窗"每次打开都变关）

### 现象
勾上「段落同步滑动释义窗」，刷新后又变成关闭，每次都得重新打开。

### 根因：不是缺字段，是"恢复之后又被默认值覆盖了一次"
`plugins` 表早就有 `enabled` 字段，`toggle()` 也确实写进去了。坏在启动时序：

1. bootstrap 恢复插件 → `states[id] = true` → `onEnable()` → 加上 `para-slider-active`
2. 紧接着 `applyLoadedPreferences(localPrefs)` → `applyVocabLayout('auto', card, true)`
3. 而旧版 `applyVocabLayout` 里，只要 `mode !== 'para-slider'` 就无条件执行：
   `states[id] = false` + **`LocalDB.put(plugins, {enabled:false})`**
4. 于是每次开页都把开关清成 false 并落库 → 自我强化，永远记不住

### 五条标准做法（对应五个伤口）

| 原则 | 旧代码违反处 | 改法 |
|---|---|---|
| 单一真相源 | `prefs.vocabLayout` 与 `plugins.enabled` 互相覆盖，没有主从 | 以 `plugins.enabled` 为准，prefs 只当影子 |
| 写穿（动作发生即落库） | `toggle()` 只写 plugins，没同步 prefs，两源从此不同步 | `toggle()` 末尾补 `persistSettingsToStorage()`；无记录时 upsert |
| 恢复期只读 | `skipSave=true` 仍改 states、仍写库 | `skipSave` 期间禁止写库、禁止改插件状态 |
| 默认值只在"从未有记录"时用 | 恢复完又被默认值赋一次 | `if (states[id] === undefined)` 才取 defaultEnabled |
| 状态不要挂 window 绕过边界 | 插件写 `window.vocabLayoutPref`，主程序读局部 `let vocabLayoutPref`（`let` 不挂 window，是两份） | `ReaderApp.setVocabLayout()` 显式 API + `Object.defineProperty` 做兼容代理 |

### 改动
- 主程序：新增 `isSliderPluginEnabled()` / `disableSliderPlugin()`；`applyVocabLayout` 加恢复期守卫；
  新增 `ReaderApp.setVocabLayout()`；`window.vocabLayoutPref` 用访问器代理到局部变量（旧插件不改也能生效）；
  `toggle()` 改 upsert 并同步 prefs；恢复循环加 `builtin` 标记与 `renderPluginUI()` 收尾
- 插件 `plugin-para-vocab-slider.js`：`onEnable/onDisable` 改调 `app.setVocabLayout()`

### 验证
抽出文件里的真实函数跑四种时序：
- 插件开启 + 恢复传 auto → `layout=para-slider`，class 保留，**0 次写库**
- 插件关闭 + prefs 残留 para-slider → 降级 auto，卡片选中 auto
- 用户主动切「右侧单列」→ 联动关插件，写库 `[false]`
- MySQL 二次恢复再传两次 auto → 状态不丢

### 注意
修好之后，库里当前存的还是 `enabled:false`（bug 期间写坏的），所以**需要手动打开一次做"播种"**，之后就一直记住了。

### 功能
- **双击正文任意单词** → 加入生词本（会取消掉两次单击触发的朗读，不会读两遍）
- 工具栏按钮「🃏 复习 (N)」，N = 今日待复习数，有待办时变橙色
- 闪卡：看词回想 → 点卡片/空格翻面 → 按 1/2/3/4 评分（忘了/模糊/记得/简单）
- 卡片上有发音按钮；底部可把该词从生词本移除
- Esc 关闭；一轮最多 30 张，答错的 10 分钟后重新进队

### SM-2 简化版调度（实测）
| 操作 | 行为 |
|---|---|
| 忘了 | 间隔清零，10 分钟后再来，ease −0.2（下限 1.3） |
| 模糊 | 间隔 ×1.2（至少 1 天），ease −0.15 |
| 记得 | 间隔 ×ease（首次 1 天） |
| 简单 | 间隔 ×ease×1.3（首次 3 天），ease +0.15（上限 3.0） |
| 上限 | 365 天 |

连续「记得」实测间隔：1 → 2.5 → 6.3 → 15.8 天。

### 存储取舍
存 `localStorage['lt_srs_v1']`，**不碰 IndexedDB 也不碰 MySQL**。理由：
插件无法参与 `LocalDB.init()` 的 version 升级，自己加 objectStore 会冲突；localStorage 几千词也就几百 KB，改起来还不会污染业务数据。
代价：换浏览器或清缓存会丢，需要多端同步再改成走桥接写 MySQL。

### 工程细节
- 事件监听只绑一次（`window._srsDblBound`），并用 `window.__srsPlugin` 指向最新实例，
  避免"删除插件后重新导入"时旧闭包指向旧对象
- 双击判定限定在 `.gloss-paragraph` 内的 `ruby`，不干扰设置面板和词表区
- 取词用 `cloneNode + 删掉 rt`，避免把行间注音文字混进单词里

## 九、 v14.7 · 桥接服务改用 MySQL 连接池

### 问题
每个请求都 `pymysql.connect()`：TCP + 认证握手本地约 **150~200ms**。
一次收藏动作要 5~6 次 `LocalDB` 调用，叠加起来 1 秒以上——这才是"点收藏卡住"的物理原因。

### 实现（`2mysql_bridge_server.py`）
- `_ConnectionPool`：LIFO 空闲队列，`acquire` 时复用；空闲超过 5 秒才 `ping(reconnect=True)` 探活，
  超过 10 分钟直接丢弃重建
- `PooledConn` 包装器：`__getattr__` 全部透传，**只把 `close()` 劫持成"归还"** ——
  10 个端点一行都不用改
- `release()` 必做 `rollback()`：异常路径可能留着未提交事务，不清理会传染给下一个使用者
- `__del__` 兜底归还：端点 `try/except/raise` 会跳过 `close()`，靠析构函数把连接还回去
- **不加信号量**：如果用信号量卡死上限，漏 4 次服务就永久卡住。改成软上限，只告警不阻塞
- `/api/ping` 返回 `pool: {created, idle, inUse, capacity}` 便于观察
- 启动加 `_warmup()` 后台线程：提前建连接 + 跑完 340 万行 `COUNT`，否则页面首个 ping 要等 2.8 秒

### 实测
| 场景 | 改造前 | 改造后 |
|---|---|---|
| `/api/ping` | ~220ms | **4.2ms**（中位 3.7ms） |
| `/api/dict/lookup` | ~220ms+ | **8.4ms** |
| 首次启动 | 3.0s | 3.0s（预热在后台，端口先起来） |
| 未 close 直接丢弃 | 连接泄漏 | `__del__` 自动归还，`created` 不增长 |

### 为什么没换 aiomysql / asyncmy
本服务是单用户本机桥接，瓶颈是**握手**不是并发模型。换异步驱动要重写 10 个端点的
`async def` + `await req.json()`，收益远小于风险。够用、够稳、够快。

**已知取舍**：端点是 `async def` 但内部是阻塞的 pymysql 调用，会占住事件循环，
所以并发请求实际是串行的。单用户场景下每次 9ms，一串 5 个也就 45ms，无感。
真要并发再改成 `def` + `Body(...)` 让 FastAPI 丢线程池，那是另一轮活。

## 十三、 原版排版渲染（iframe srcdoc + 每本一个开关）

### 后端 `/api/dict/render`
一次给齐三样：`{html, css, js}`。

**关键设计：不登记样式文件名，而是从词条 HTML 里反查。**
词条本身写着 `<link rel="stylesheet" href="oald10.css">`、`<script src="oald10.js">`，
拿这个 href 去 mdx 同目录读文件，换词典永远不会配错。读取前做了路径越界防护（`../` 一律拒绝）。

CSS 缺失时走回退链：词条声明 → `dict_sources.css_file` → `entry.css` → 目录里任意 `.css`。
（麦克米伦同义词典的 HTML 写的是 `mmt.css`，但文件根本没随包提供，靠回退拿到 `entry.css`。）

返回前把 `<link>` `<script>` 从 HTML 里剔掉，避免 iframe 再去请求不存在的相对路径。

### 前端
- 每张词典卡片右上角一个「原版排版 / 文本」按钮，点了就在两种渲染之间切
- Setting 第 6 组「权威词典渲染方式」：每本一个开关，**记住默认用哪种**（存 `prefs.dictRender`）
- 渲染用 `iframe.srcdoc`：`<style>` 内联该词典 CSS + body 内容 + 词典 JS，**天然样式隔离**，
  不会和主程序的 class 打架

### 两个坑
**① iframe 高度**：`file://` 页面读子 iframe 的 `contentDocument` 会跨域报错。
改成 iframe 内部自己量 `scrollHeight` 再 `postMessage({__authH})` 给父页面，父页面按 `e.source` 匹配对应 iframe 设高度。
（load + 120ms + 500ms + 1500ms + ResizeObserver 各发一次，防止字体/布局晚到。）

**② 图片全裂**：OALD 的牛津3000/CEFR 徽章、朗文的喇叭、麦克米伦的英美音标旗全是 mdd 里的图片，
还没导出。现在统一 `img{display:none!important}` 先藏掉，等第 4 步导出后删这一行就行。

## 十六、 词性精度修复（4 个错，一个比一个隐蔽）

### 错 1：牛津用错了选择器
原来取 `.o-pos-tag`，那只是**当前那一段**的词性标签。真正的完整列表在 `.o-pos-tab`（顶部的词性切换页签）。
所以 `record` 只拿到第一个词性。改用 `.o-pos-tab`，`record` → `n./v.`，`well` → `adv./adj./exclam./n./v.`。

### 错 2：白名单把真词性挡掉了
原来的 `_POS_OK` 是白名单（adj|adv|n|v|…），于是牛津的 `det.`、`definite article`
全被判为"不是词性"→ `the` 的词性是空的。
改成**形态判断 + 小标题黑名单**：小写开头、只含字母/点/连字符/空格、长度 ≤24，且不在
`{idioms, idm, phr v, phrasal verbs, word family, …}` 里。这样既不会漏 `det.`，也不会收 `IDIOMS`。

### 错 3：朗文用了后代选择器（最隐蔽）
`.entryhead .pos` 会匹配 `entryhead` **内部所有后代**的 `.pos` —— 也就是整个词条下几百个义项的词性。
`record` 一次返回 **700 多个** noun/verb/adjective，`happy` 多出 noun/adverb。
改成 `.entryhead > .pos`（直接子元素），立刻干净：
`happy` → adjective，`record` → noun/verb。

### 错 4：麦克米伦一个标签里塞了两个词性
`<span class="PART-OF-SPEECH">adverb, preposition</span>` —— 不拆就是一条 `adverb, preposition`。
按 `[,/]` 拆开再清洗。

### 顺带的健壮性修复
`ON DUPLICATE KEY UPDATE` 里 `raw_z=VALUES(raw_z)` 改成 `COALESCE(VALUES(raw_z), raw_z)`，
`raw_size` 同步保护。这样 `--no-raw` 重跑（例如只为刷新词性）**不会把已存的原文冲成 NULL**。

### 修复前后
| 词 | 牛津 | 朗文 | 麦克米伦 |
|---|---|---|---|
| the | ∅ → **definite article** | definite article → **definite article/determiner/adverb** | determiner |
| record | noun → **n/v** | noun → **noun/verb** | noun/verb/adjective |
| happy | adj → **adj**（去掉多捞的 noun/adverb 之前是 adjective/noun/adverb） | | |
| about | prep/adv/adj | preposition/adverb/adjective | adverb/preposition |

### 一个操作失误
注入初始化代码时，`replace` 命中了第一个 `ensureUIInjected();`，而它在
`<script src="...jszip...">` 标签里，把标签插坏了。已修复并改到 `bootstrap` IIFE 末尾调用。

### 根因：服务一直是旧进程（踩了很久才发现）
用户多次"重启"后页面仍缺「权威词典对照」，前端其它部分却是新的。
`curl` 正在跑的服务发现 `/api/dict/multi` 返回 **404** —— 跑的根本不是新代码。

**为什么重启不生效**：`start_bridge.vbs` 只负责启动，**不会杀掉旧进程**。
旧进程占着 8080 时，新实例绑定失败（`address already in use`）直接退出，
表面上看"重启了"，实际一直是旧代码在服务。

**做了一个 `restart_bridge.bat`**：
```bat
for /f "tokens=5" %%a in ('netstat -ano ^| findstr ":8080" ^| findstr "LISTENING"') do taskkill /f /pid %%a
start "" /min "python.exe" "2mysql_bridge_server.py"
curl -s -X POST .../api/ping
```
先按端口杀进程（不按进程名，避免误杀别的 python），再启动，最后自动健康检查。
**注意：`.bat` 必须写成纯 ASCII**——`chcp 65001` 改不了 cmd 解析整个文件的代码页，
中文会变成乱码甚至解析错误。

## 二十四、文字版 PDF（考研真题）结构化解析（2026-11-17）

**用户问"HTML 添加文件能加 PDF 并解析吗"**：查代码发现**早就支持**——
