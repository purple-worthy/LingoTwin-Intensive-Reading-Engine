# LT 划词词典 · 浏览器插件

> **主线副本：`v17/extension/lt-lookup/`**（随 LT-Reader v17 主线维护）。
> 历史路径 `v14/`、`v16/extension/lt-lookup/` 仅作留存。**v17 起模型侧全面改用 OpenAI 兼容接口**（`/v1/chat/completions`、`/v1/models`），插件本身不直连模型——段落翻译经桥接 37701 转发，桥接内部已升级。

在任意网页上**双击单词**或**划选英文**，即可看到 **牛津10 / 朗文6 / 麦克米伦 / 麦克米伦同义词** 四本词典的对照释义，
带英/美音标、双喇叭发音、词性占比、中文释义、双语例句、近义词/反义词/短语/搭配。

新增：**整段选中 → 本地 Ollama 翻译 + 自动挑出重难点词**；**结果里继续双击查词，逐层返回，不限层数**；
**面板可拖动、四边缩放、五种预设位置**；**查词自动存档，随时回看（刷新不丢）**。

数据全部来自你本机的 MySQL 桥接服务（`127.0.0.1:37701`），不联网、不上传（段落翻译由桥接转发到你本机的 OpenAI 兼容模型服务，v17 起为 `/v1/chat/completions` 接口）。

## 一、安装（Chrome / Edge 通用）

1. **先启动服务**：双击 `F:\EnglishReaderDataDict\restart_bridge.bat`
   （先杀掉占着 37701 的旧进程，再启动新的，最后自动健康检查）
2. 打开 `chrome://extensions/`（Edge 是 `edge://extensions/`）
3. 右上角打开 **开发者模式**
4. 点 **加载已解压的扩展程序**，选择本目录：
   ```
   E:\Code\WebCode\Demo01\v16\extension\lt-lookup
   ```
5. 装好后点一下工具栏上的插件图标：角标 **ON** 表示连上服务，**OFF** 表示服务没起
6. 段落翻译需要本地模型服务在跑（`http://127.0.0.1:11434`，v17 起桥接用 OpenAI 兼容 `/v1` 接口调用）。**没起也能用**——重难点词照常分析，只是没有译文。

> 想在**本地 html 文件**（`file://`）上也用：在扩展详情页把 **允许访问文件网址** 打开。
> 改了插件代码后，回到扩展页点一下 **重新加载** 才会生效。

## 二、怎么用

### 2.1 触发查词

| 动作 | 效果 |
|---|---|
| **双击**网页上的英文单词 | 直接查词（不用点放大镜） |
| **选中** 1~4 个英文单词 | 光标下方浮出「🔍 查 “xxx”」，点它查词 |
| **选中一段**（>4 词或 >60 字符） | 浮出紫色「🌐 翻译 + 难点词」，点它分析整段 |
| 点 🔊 | 浏览器朗读（英音 / 美音分开） |
| 点某本词典的标题栏 | 收起 / 展开那一本 |
| `Esc` / `✕` | 关闭面板 |

### 2.2 移动和缩放面板

| 操作 | 效果 |
|---|---|
| 拖动**标题栏** | 把面板放到屏幕任意位置（会记住） |
| 拖动**左/右边缘** | 左右伸缩 |
| 拖动**上/下边缘** | 上下伸缩 |
| 拖动**右下角** | 同时改宽高 |
| 标题栏 `⇋` | 循环切换 5 种预设：右侧 → 左侧 → 底部 → 顶部 → 居中 |
| 标题栏 `📌` | **固定当前结果与位置**：图钉变红、面板红框；固定后新划词/双击不会覆盖当前结果，也不能拖动或切位置。再点一次解除 |
| 标题栏 `◐` | 展开**背景透明度**滑条（35%~100%），实时生效，自动记住 |
| 窗口缩放 | 面板自动重新贴边，不会跑出屏幕 |

### 2.3 嵌套查询与返回

- 在**例句、释义、查词卡正文**里双击单词 → 新结果**覆盖**当前页面
- 在段落结果里点绿色的难点词 → 直接查那个词
- 在结果里再选中一段 → 继续做段落分析
- 左上角 `←` **逐层返回**，旁边显示当前层数（如 `3 层`）
- **不限层数**；每一层返回后滚动位置也会还原

独立查词页（`lt_reader_v16.html`）里的浮层用的是同一套逻辑，体验一致。

### 2.4 查词记录（自动存档）

每查完一个词，**只把基础索引**存到浏览器本地（`chrome.storage.local`，刷新/重启浏览器都不丢）：
`词 + 音标 + 释义摘要 + 时间`。**不存四本词典的完整内容**——那些本来就在本地词库里，
点开记录时现查一次就能拿到最新结果，既省空间，又不会因为词典更新而看到过期快照。

| 操作 | 效果 |
|---|---|
| 点标题栏 `🕘` | 打开/关闭「查词记录」列表，按最近查询排序 |
| 点列表中的某个词 | **重新查一次词库**，显示最新词典结果（不是旧快照） |
| 点条目右上 `✕` | 删除单条记录 |
| 记录栏「清空」 | 清空全部记录（带二次确认） |

- 同一个词重复查：自动去重并置顶，更新记录时间（不会堆一堆重复）。
- **不设条数上限**——每条只有几个字段，占空间极小，想存多少存多少。
- 只记录**单词查询**；段落翻译不存（那是译文，不是查词）。
- 记录存在扩展的独立存储里，和面板位置/透明度那些设置分开，互不影响。
- 清除浏览器扩展数据会连带清掉这些记录，重要词条建议同时用主程序的「📁 单词查询归档」长存。

### 2.5 别名自动跟随

查 `delegates`、`happier` 这类词时，词典里存的往往是 `@@@LINK` 别名（本身没有释义）。
后端会**自动跟随到原型词**（`delegate` / `happy`），词典卡里只用一句话提示"是别名"，
下面直接显示原型词的完整释义、例句、音标和原版排版——不用再点第二次链接。

## 三、重难点词的标准怎么改

配置文件就一个文件：

```
F:\EnglishReaderDataDict\2mysql_bridge_server.py
```

### 3.1 只改一个值（最常用）

在文件靠前的「段落分析：重难点词判定标准」那一节：

```python
DIFFICULTY_LEVEL = "B2"   # 可选 A1 / A2 / B1 / B2 / C1 / C2
```

- 想**更严格**（只挑很偏的词）→ 改成 `C1` 或 `C2`
- 想**多标一些**（宽松）→ 改成 `B1` 或 `A2`

改完**重启服务**才生效（`restart_bridge.bat`）。

### 3.2 进阶配置

同一个文件里的 `DIFFICULT_WORD_CONFIG` 字典，可以调：

| 键 | 含义 | 默认 |
|---|---|---|
| `max_words` | 一次最多返回几个难点词，`0` = 不限 | 15 |
| `min_score` | 得分门槛 | 1 |
| `min_length` / `length_bonus` | 长词加分 | 7 / 1 |
| `include_unranked` | 词频表未收录的词算难点 | True |
| `academic_bonus` | 雅思/托福/GRE/考研标签加分 | 1 |
| `collins_min_star` / `collins_bonus` | 柯林斯星级加分 | 3 / 1 |
| `comfortable_coverage` | 目标理解覆盖率（只用于展示） | 0.98 |
| `ollama.model` | 翻译用的模型 | `qwen3:4b-instruct-2507-q4_K_M` |
| `ollama.timeout_sec` | 翻译超时 | 45 |

### 3.3 这个标准是怎么定的（网上查的依据）

| 来源 | 结论 |
|---|---|
| Laufer (1989) | 认识文本 **95%** 的词才能基本理解 |
| Hu & Nation (2000) | 上修到 **98–99%**，即每 50~100 词才允许 1 个生词 |
| Nation | 高频词 = 最常用 **2,000 词族** |
| Schmitt & Schmitt (2014) | 中频词 = **3,000–9,000 词族**，正是达到 98% 覆盖率必须掌握的 |
| CEFR 词族量 | A1 500–800、A2 1,000–1,500、B1 2,000–2,750、**B2 3,250–4,000**、C1 5,000–7,000、C2 8,000+ |
| AWL 学术词 / 学科词 | 通常落在中频之外，对普通学习者同样是重难点 |

实现上用 **ECDICT 的 `frq` 词频排名**近似 CEFR 等级：
低于你设的目标水平 → 不标；同级 +1 分，每高一级再 +1，词频表外 +3；
再叠加长词、实词、考试标签、柯林斯星级等加分，按总分排序返回，每个词都带**人类可读的判定理由**。

> 说明：这是**学习用途的近似分级**，不是官方 CEFR 分级测试。frq 是语料词频，和 CEFR 的定性描述只能近似对应。

## 四、为什么要在 background 里转发请求

插件的内容脚本运行在网页里。如果网页是 `https://`，从它直接请求 `http://127.0.0.1:37701`
会被浏览器判定为**混合内容**直接拦掉。

所以请求统一由 `background.js`（service worker）发出——它带着 `host_permissions`，
不受页面混合内容的约束。这是这类「本地服务 + 网页插件」的标准做法。

## 五、出问题怎么查

| 现象 | 原因 / 处理 |
|---|---|
| 面板提示"连不上本地词典服务" | `restart_bridge.bat` 没跑或失败。看 `F:\EnglishReaderDataDict\bridge_server.log` |
| 点图标角标是 OFF | 同上，服务没起 |
| 划词没反应 | 页面可能禁止选区（PDF 阅读器、部分网盘预览）；先手动选中再松鼠标 |
| 双击没反应 | 有些站点自己吞了 `dblclick`；改用选中 + 点放大镜 |
| 段落没有译文 | 本地模型服务（Ollama 等）没启动，或桥接的模型接口配置有误。重点词仍正常，启动服务后重试即可 |
| 面板样式被网页影响 | 不该发生——UI 挂在 Shadow DOM 里。真遇到请截图 |
| 词典区是空的 | 服务是旧版本。用 `restart_bridge.bat` 重启，别只双击 `start_bridge.vbs`（它不杀旧进程，新实例会因端口占用直接退出） |
| 改了配置没生效 | 服务只在启动时读配置，必须重启 |

## 七、已知限制

- 只支持英文单词/短语（中文查词没做，本地库没有中英反查索引）
- 发音走系统 TTS，音色取决于系统语音包；词典 mdd 里的真人音频没导出
- 段落最长按 6000 字符送给后端；模型 `num_ctx=4096`，太长会被截断
- Chrome 会拦截 `chrome://`、扩展商店等特殊页面的脚本注入，那些页面上不工作
- 面板位置和层级存在浏览器 `localStorage`（通过 `chrome.storage.local`），换浏览器配置不通用
