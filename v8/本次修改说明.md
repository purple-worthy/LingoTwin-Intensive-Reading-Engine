# IELTS精读阅读器 v8.0 架构升级方案

## 一、报错与逻辑问题根因诊断

### 现象

Ollama API 返回 404；未建立连接时界面就提前展示 `qwen3.5:9b`

1. **虚假状态 Bug**
   上一版代码在 `select` 标签内硬编码写死假模型选项：`<option value="qwen3.5:9b">qwen3.5:9b (默认)</option>`。
   问题：**还没连通 Ollama，界面就误导用户模型已选中**。
2. **404 报错真实原因**
   你通过 IDEA 内置预览服务打开页面（地址 `localhost:63342`），404 两种常见诱因：

- Ollama 地址配置携带多余路径；
- 本机不存在名称完全匹配的模型标签（比如实际是 `qwen2.5:7b`），新版 Ollama 当模型不存在时，`/api/generate` 直接返回 `model 'xxx' not found`。

### v8.0 修复方案

- 删除所有写死的假默认模型；
- 初始状态展示：⚠️ 未连接 Ollama（请先点击探测连接）；
- 调用 `/api/tags` 探测成功后，**动态拉取本地真实模型列表**，绿灯标识就绪；
- 捕获 `api/generate` 返回异常，直接展示 Ollama 返回的原始错误信息。

## 二、IndexedDB 存储问题说明 & 两种本地持久化方案

### 核心疑问：不同 HTML 是否会新建数据库？

浏览器按照 **Origin（协议+域名+端口）** 隔离 IndexedDB：

- 同源：都在 `[http://localhost:63342](http://localhost:63342)` 打开，共用一套数据库；
- 源变化：更换端口、直接双击文件以 `file://` 打开，会创建全新独立库；
- 底层存储：IndexedDB 物理文件存放在 Chrome/Edge 用户数据沙盒（C盘），JS 受浏览器安全限制，**无法直接修改数据库物理路径**。

### 方案A：File System Access API（推荐，无需后端）

现代 Chrome / Edge 原生支持 `window.showDirectoryPicker()`
v8.0 新增功能：📂 绑定本地工作文件夹

- 用户自选任意盘符目录（例如 `D:\EnglishReaderData`）；
- 授权一次后，文章、书本、词典数据自动以明文 `.json` 写入该目录；
- 彻底脱离C盘浏览器沙盒限制。

### 方案B：轻量网关桥接（对接 MySQL / ECDICT / MDX离线词典）

浏览器原生 JS 不能直连 MySQL 3306端口，也无法直接读取GB级 `.mdx` 词典文件。
v8.0 设置页新增：🗄️ 外部数据库 / 本地词典 API 网关配置
配套提供 ECDICT 词典快速导入工具。
