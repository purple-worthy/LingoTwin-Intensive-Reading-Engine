## V15 阅读进度持久化「最近阅读」（16:48）

用户要求记住往期打开点位、持久化并可更新。方案是**三层分工，不是二选一**：

| 层 | 载体 | 作用 |
|---|---|---|
| 同步快取 | localStorage `reader_last_position_v15` | 刷新瞬间拿到"上次读哪篇"，不等异步 |
| 离线全量 | IndexedDB `reading_progress` store | 无 MySQL 也持久化全部历史点位 |
| 多端同步 | MySQL `reader_reading_progress` 表 | bridge 连上时跨设备同步 |

**前端**（`lt_reader_v15.html`）：
- `ProgressStore` 状态机统一 CRUD：`readLastSync/loadAll/list/get/save/remove`，暴露 `window.ProgressStore`。
  save 三层同时落、失败静默降级；loadAll 用 updatedAt 比较合并（远端更新则覆盖本地）。
- 数据模型 `{articleId(主键), title, paragraphIndex, scrollY, scrollLeft, updatedAt}`。
- `inferParagraphIndex()` 按视口顶部最近的 `.para-block` 推断读到第几段；
  `captureCurrentProgress()` 捕获+持久化；滚动 500ms 防抖 `scheduleProgressSave()`；
  `applyProgressToView()` 按段落 offsetLeft/top 恢复（横向回退 scrollLeft）。
- 监听：readerRoot scroll + window scroll（纵向）+ pagehide 立即落盘。
- `openArticleById(id, opts)` 加 opts：换文前存旧文进度，打开后恢复目标进度；
  `opts.restoreProgress=false` 可强制从头（新建/导入后）。
- bootstrap：`await ProgressStore.loadAll()` → 读同步快取候选 id（校验仍在目录树中）→
  恢复上次篇章与段落点位；删节点时 `ProgressStore.remove()` 联动清理。
- UI：顶部「🕒 最近阅读」按钮 + `recentDrawer` 抽屉，按 updatedAt 倒序列出，
  点击 `resumeProgress()` 跳转恢复，支持单条删除；`closeAllDrawers` 已纳入 recentDrawer。

**后端**（`F:/EnglishReaderDataDict/2mysql_bridge_server.py`，已备份 `.bak_时间戳`）：
