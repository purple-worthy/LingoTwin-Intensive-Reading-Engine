## 追加：朗读三个 bug 的根因与修复（v15.3，凌晨）

### ① 两种声音同时读（重大）
根因：`_playChunks` 的降级 `bail()` 只暂停元素，但旧序列的 `el.onended` 仍会 `playAt(i+1)`，
而 `playAt` 只校验 `token` —— 降级时 token **没变**，于是旧链继续、新链从头开始，两条链同时出声。
另外 `stop()` 只暂停 `_curAudio` 一个元素，尚未触发 `playing` 的元素完全没被管到。
修复：
- 每次播放分配 `seqId`，`stop()` 里 `++_seq`，`alive()` 同时校验 token + seqId + dead
- `bail()` 先 `dead = true` 再降级
- 加全局 `_liveEls` 注册表，`_pauseAll()/_killEl()` 暂停并 abort 所有在途请求
- `_playDictAudio` 超时后迟到的 `playing` 必须立刻 `pause()`（有道路径的同类问题）

### ② 句间长停顿
两个来源：降级时旧链复活（同上）+ 高语速下合成赶不上播放。
修复：
- 分块 ≤12 块时**一开始就全部排队**（`prefetch(0)` + eager），3x 语速实测间隙 0~1ms
- `_chunk` 超长句改为按 逗号/分号 → 空格 切，绝不从单词中间劈开
- Kokoro 看门狗放宽到 首块 10s / 后续 12s，避免误判断路

### ③ 语速 + 停止条
- 语速下拉扩到 19 档：0.25/0.5/0.6…2.0/2.5/3.0；Kokoro 只吃 0.5~2.0，超出用 playbackRate 补齐
- 新增悬浮停止条 `#ttsStopBar`：可拖拽（位置存 `lt_tts_stopbar_geom`）、单击即停、
  自动跟随播放状态显隐（700ms 轮询 `_liveEls` + speechSynthesis.speaking）
- 喇叭按钮朗读中变 `🔇`（短按钮）或 `⏹ 停止`（长按钮），再点一次即停止
- 只有 >24 字符才显示悬浮条，查单词不闪

## 修复：工具条图标"点了没反应"（v15.5，04:10）

**根因**：`bindDrag()` 在 `pointerdown` 里就 `setPointerCapture(pointerId)`。
指针被容器捕获后，`pointerup` 的目标变成容器，按规范 `click` 只会派发到
pointerdown/up 目标的**最近公共祖先** —— 也就是 `#ltDock`，按钮自身的 click 永远收不到。
表现：图标都在，但点哪个都没反应。

**修复**：pointerdown 只记录起点；拖动超过 4px 再用 `window.addEventListener('pointermove'/'pointerup')`
跟踪（不再用 setPointerCapture）；拖完用 capture 阶段的 click 吞掉误触。

**顺带修掉**：顶/底按钮原来用 `disabled`，页面高度变化后状态不刷新（切页/导入后高度变了但不触发 scroll），
导致"返回底部"永久禁用。改成 `.dim` 类（视觉变灰但可点）+ `scrollPage` 里 `atEdge()` 提前返回
+ 每 900ms `syncButtons()` 兜底。

**教训**：验证 UI 交互不能用 `element.click()`（绕过命中测试），必须用 CDP
`Input.dispatchMouseEvent` 走真实命中；`setPointerCapture` 与按钮点击天然冲突，浮层拖动要慎用。
