# 2026-11-19

## 插件面板内划词 / 双击失效（v14/extension/lt-lookup，1.0.0 → 1.0.1）

**现象**：网页正文划词、双击正常；插件自己返回的结果面板内，划词与双击全部无反应。此前多轮修改未解决。

**取证方式（以后照这个来）**：Chrome `--headless=new --remote-debugging-port` + CDP `Input.dispatchMouseEvent` 派发真实鼠标事件，`Runtime.evaluate` 读真实选区与命中测试。不靠猜。

**四个根因（均已实测确认）**

1. `window.getSelection()` 在 Shadow DOM 内返回 **collapsed 假选区**（anchor 指向 HTML）。同一时刻 `shadowRoot.getSelection()` → `collapsed:false` 且 rect 正确。面板内 `onBodyMouseUp` 第一行就 return 了。
2. `document.caretRangeFromPoint()` **不穿透 shadow**：在面板内返回 `startContainer.nodeType=1`、parent=HTML。原注释"能穿透"是错误假设，导致 `pickWordFromEvent` 取词为空。
3. chip `z-index:2147483646` < panel `2147483647` 且 DOM 顺序在前 → 面板内划词的放大镜 100% 被面板盖住（即使事件修好也看不见）。
4. `scheduleAutoClose()` 无条件 `panelHovered=false` 再排期；`mouseenter` 在"面板已开、鼠标已在里面"时不会重触发 → 面板内查词 2.5s 后面板自动关，表现为"没反应"。

附带：网页划 2~4 词短语被 `validWord` 丢弃（面板内已放行、网页没同步）；双击取词因 focus 停在下一词首，"quick" 会取成 "brown"。

**修复要点**
- `selectionFor(root)`：ShadowRoot 用 `root.getSelection()`，否则回退 `window.getSelection()`。
- `pickWordFromEvent`：选区优先、caret 兜底，`inShadow` 时不用 document caret。
- `wordFromSelection`：选区内只有一个英文词就直接用。
- chip 与 panel 同 z-index，`shadow.append(style, panel, chip)` 让 chip 压顶。
- `scheduleAutoClose`：悬停不排期，到点用 `:hover` 复核（panel + chip）。
- 网页与面板的划词判定统一：含英文字母即放行。

**验证结果**：6 场景全过 —— 网页短语划词 chip 可见、网页双击取 "quick"、面板内划词 chip 命中 `lt-chip`、面板内双击 depth+1 且 3.2s 后面板仍在、长文本→段落翻译出译文、鼠标移出 3.3s 后面板自动关。

**教训**：Shadow DOM 内的选区与坐标不能复用 document 的 API，必须以浏览器实测为准。

## 追加：双击「跳词 / 查字母」（插件 1.0.2）

用户复测：选中一个词，查到的却是它前面/后面的词，或查出一个字母。

**真因（实测）**
1. **双击词尾 1~2px 时浏览器根本不选词**（选区 collapsed），`caretRangeFromPoint` 的插入点已落到下一词首字母 → 按字符扩词必偏。实测：quick 右缘→brown、jumps 右缘→over。
2. 单词被拆在多个内联节点（逐字母 span）时只取到片段，查出 "d"。
3. 面板内双击音标 `/t/`：几何已被拦，但选区兜底又把它捞回来，查出 "t"。

**修复**
- 新增几何取词 `wordAtPoint()` / `findWordInElement()`：按每个词的 Range 矩形命中点击点（1px 容差），排在选区/caret 之前。
- `expandWordAcrossNodes()`：跨内联节点按字母连续性补全；文本无兄弟时向 inline 父级借一层；跳过 `<rt>/<rp>`。
- `isLabelHit()`：面板音标/词性/级别标签直接不查。
- 选区兜底加 12px 距离校验。
- manifest 1.0.0 → 1.0.1 → **1.0.2**。

**验证**：合成排版 23 场景 0 FAIL；真实 `ielts_book_v2.html`（6 段 / 165 个 ruby）14 场景 0 FAIL；性能 0.01ms/次，最坏（段落空白）0.08ms/次。

**教训**：字符偏移取词天生不可靠——浏览器在词边界的行为不一致（左缘选中、右缘不选）。几何矩形是唯一稳定判据；跨节点拼词必须处理，否则 ruby/逐字母结构必查片段。

**用户确认（20:24）**：插件 1.0.2 实测通过，面板内划词/双击、网页取词均正常，跳词与查字母问题解决。
