## 手机迁移方案咨询（纯讲解，未动手）

- 用户目标：把 LT-Reader 搬上手机当无广告自研 App。**选择：安卓优先 / 先联网以后再离线 / 只讲原理自己动手。**
- 关键发现（纠正初判）：`lt_reader_v15.html` 里两个后端地址**不是写死，是运行期可配置**——
  桥接地址 `getBridgeUrl()` 读 localStorage（2032 行默认值 127.0.0.1:8080），
  Ollama 地址是 Setting 的 `ollamaUrlInput`（661 行默认 localhost:11434）。改配置即可，无需改代码。
- 迁移本质 = 把两个后端服务重新安置；地址填对只是第一步，三大隐藏前提：
  ① 服务端监听 `0.0.0.0` 而非 `127.0.0.1`（FastAPI/Ollama 默认只认本机，手机连不上＝头号杀手）；
  ② Windows 防火墙放行入站端口；③ 手机电脑同网段（访客 WiFi 隔离会坑）。
- 另两个坑：HTML 不能 file:// 打开须 http 托管（否则跨域）；html 与 api 端口不同＝不同源，FastAPI 需加 CORS。
- **核心矛盾**：PWA/Service Worker 安装要求 HTTPS，局域网 http 拿不到安装提示 → 先用浏览器书签验证，
  真要 PWA 得内网穿透/上云拿 HTTPS。套壳 App 与 PWA 只是分发外壳不同，后端仍在 PC＝离开 WiFi 就废。
- 下一步若要落地：先阶段0（http 托管 + host 0.0.0.0 + 防火墙 + 同 WiFi 书签）验证，再谈 PWA/套壳。
- **12:11 决策收尾**：用户权衡后明确「继续在电脑上用」，搁置手机迁移。核心理由：手机方案真成本在
  维护两套后端/数据，而桌面端满血体验（大屏/键鼠/双击查词/划词/图钉透明度插件）本就为桌面设计，
